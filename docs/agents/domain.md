# Domain docs

## Layout

This project uses a single context:
- GLOSSARY.md at the project root
- docs/adr/ for architecture decision records

## Before exploring

Read GLOSSARY.md and ADRs relevant to the area being explored.
If these files do not exist, proceed silently.
Create them through domain modeling as terms and decisions are resolved.

## Vocabulary and decisions

Use glossary terms when naming domain concepts in issues, code,
tests, and proposals.

If a needed concept is missing, reconsider the terminology or note
the gap for domain modeling.

If a proposal conflicts with an existing ADR, explicitly identify
the conflict and explain why the decision should be reconsidered.
